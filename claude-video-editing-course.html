How this course works

  1. Start at your level. Beginner, Intermediate and Professional each have their own curriculum. New to the subject? Begin at level one.
  2. Watch, then read the notes. Every session has one trusted YouTube tutorial, session notes with the points to remember, and a part-by-part guide that opens the video at each timestamp.
  3. Do the practice task. Skills come from doing. Every session ends with something to make.
  4. Pass the module quiz. Each module ends with a short quiz. Pass it to complete the module — retry as often as you need.
  5. Earn a certificate per level. Mark sessions complete — progress is saved in this browser — and unlock a certificate at each level.

What you need

  • A Claude account: the free plan covers the beginner level. Claude Code, used from the intermediate level, needs a paid plan.
  • A computer: Mac or Windows. The Claude Code sessions install free tools such as FFmpeg; no coding experience is needed.
  • Footage: your own clips from a phone are enough. Work on copies, never on your only original files.
  • For the DaVinci Resolve session: the AI connection may need the paid Studio version. You can follow the idea with any editor.
  • Time: about 5 hours of video across all three levels, plus practice.

Session 1.1

Getting started with Claude

What Claude is, how the app is laid out and what it is good at.

Video referenceClaude AI Tutorial for Beginners (Step-by-Step)Kevin Stratvert · 8:37 · YouTube ↗

Session notes
  • Claude is an AI assistant you talk to in plain language; you can attach documents, images and transcripts.
  • It works best on thinking and writing tasks: outlines, scripts, summaries, feedback and plans.
  • It can be wrong. Check names, numbers and technical settings before you rely on them.
Detailed notes · 6 parts
  1. 0:33
    The interface

    The main area is the conversation. You can start new chats, attach files, and find earlier chats in the sidebar. Each chat starts fresh unless it is inside a Project.

  2. 1:04
    A first writing task

    Ask for something specific and say who it is for. Then ask for changes in plain language — shorter, warmer, more direct — instead of rewriting the request.

  3. 2:21
    Uploading files

    Attach a transcript, a brief or a script and ask for a summary, the key moments or the weakest sections. This is the fastest way to review long recordings.

  4. 3:18
    Artifacts

    Longer outputs such as documents and tables open beside the chat as Artifacts, which you can edit, copy and reuse. Shot lists and checklists work well this way.

  5. 5:23
    Projects

    A Project keeps instructions and reference files together for one channel or client, so every new chat already knows the context.

  6. 7:25
    Connectors and skills

    Claude can be connected to other tools and can load reusable instructions called Skills. You will use both later in this course.

Session 1.2

Prompting Claude well

How to brief Claude so the first answer is usable.

Video referencePrompting 101 | Code w/ ClaudeAnthropic · 24:53 · YouTube ↗

Session notes
  • Say who the video is for, where it will be published and how long it should be.
  • Give examples of scripts or edits you like and say why you like them.
  • Ask for a specific format — a table, a numbered shot list, a two-column script.
Detailed notes · 7 parts
  1. 1:28
    Setting the stage

    Start by telling the model what the job is and what a good result looks like. A first attempt with a thin prompt shows you what the model assumes when you say too little.

  2. 3:57
    Prompt structure

    A dependable order: the task and role, the background material, detailed instructions, examples, a reminder of the most important rules, then the output format.

  3. 5:40
    Task context

    Explain who the model is acting for and why the task matters. Context changes its choices — a caption for a luxury brand and for a student café need different decisions.

  4. 8:47
    Background detail

    Put reference material — a brief, a transcript, brand guidelines — in clearly labelled sections, separate from your instructions, so the model can refer to it precisely.

  5. 13:07
    Examples

    Examples are the strongest steering tool. Show what good output looks like and, where useful, what to avoid. Label them so the model knows they are examples, not material to copy word for word.

  6. 15:55
    Reminders

    Repeat the critical rules near the end of a long prompt: accuracy over guessing, what to do when information is missing, and anything that must never appear.

  7. 20:04
    Output formatting

    Say exactly how the answer should be laid out — headings, a table, a fixed list of fields. A predictable format is what makes a prompt reusable in a real workflow.

Practice

Write one detailed prompt for a 45-second product video script. Improve the prompt twice and keep the best version.

Session 2.1

Scripting with Claude

Writing short-form scripts that sound like you.

Video referenceHow To Use AI to Write Viral Reel Scripts - Claude Projects Tutorial100x Engineers · 12:40 · YouTube ↗

Session notes
  • Open with the hook: the first line must earn the next three seconds.
  • Give Claude your own past scripts so the draft matches your voice.
  • Read every script aloud and rewrite anything you would not actually say.
Detailed notes · 6 parts
  1. Part 1
    Set up a scripting Project

    Create a Project for the channel and add instructions describing the audience, the format and the length. Scripts written inside it will share one voice.

  2. Part 2
    Feed it proven examples

    Add transcripts of videos that performed well — yours, or from your niche for study. Ask Claude to describe what they have in common: hook type, pacing, sentence length.

  3. Part 3
    Write the hook first

    Ask for ten hooks before any full script. A hook names a problem, a surprising claim or a clear promise in one sentence. Pick one and build the script around it.

  4. Part 4
    Structure the body

    Use a simple pattern: hook, context in one line, three points or steps, payoff, call to action. Ask Claude to mark where the picture should change.

  5. Part 5
    Make it sound human

    Read the draft aloud. Shorten long sentences, replace formal words and add your own examples. Tell Claude what you changed so the next draft improves.

  6. Part 6
    Review against the transcript

    After filming, paste the real transcript back and ask what to cut. The best scripts are finished in the edit.

Screenshots are frames from the video, served by YouTube. Tap a time to open the video at that part.

Practice

Write three 30-second scripts on one topic with different hooks. Record the one that sounds most natural.

Session 2.2

Titles, hooks and packaging

Using Claude to generate and test the promise your video makes.

Video referencegive me 8 minutes, I'll make your titles 81% betterAprilynne Alter · 7:45 · YouTube ↗

Session notes
  • Decide the title and thumbnail idea before editing — it tells you what the video must deliver.
  • Ask for many options, then choose with your own judgement; volume is what AI is good at.
  • A title should create curiosity without lying about the content.
Detailed notes · 6 parts
  1. 0:00
    Why titles matter

    The title and thumbnail decide whether anyone watches. Treat them as part of the edit, not a task for the end.

  2. 0:32
    Creating curiosity

    A strong title opens a question the viewer wants answered. Give enough to interest them and hold back the answer.

  3. 1:28
    Modelling proven formats

    Study titles that worked in your niche and reuse their structure with your own topic. Ask Claude to extract the pattern from a list of successful titles.

  4. 2:46
    Power words

    Specific, emotional or concrete words outperform vague ones. Numbers, time frames and clear outcomes make a promise believable.

  5. 4:39
    Keeping titles short

    Cut every word that does not add meaning. Long titles are truncated on phones — the important words must come first.

  6. 5:44
    Testing and changing

    A title can be changed after publishing. Prepare two or three alternatives in advance and swap if the video underperforms. Never promise what the video does not deliver.

Session 3.1

Claude Code for non-coders

What Claude Code is and how to use it without programming knowledge.

Video referenceClaude Code Tutorial for Non-CodersKevin Stratvert · 9:35 · YouTube ↗

Session notes
  • Claude Code works inside a folder on your computer: it can read, create and change files there.
  • It asks permission before running commands. Read what it proposes before you approve.
  • Always point it at a copy of your project, never at your only originals.
Detailed notes · 7 parts
  1. 0:00
    What Claude Code is

    Despite the name it is not only for programmers. It is Claude with the ability to work with files and run tools on your computer, directed in plain language.

  2. 1:09
    Choosing the app

    Claude Code is available in the desktop app and in a terminal. The desktop app is the easier starting point if you have never used a command line.

  3. 3:11
    Plan mode and permissions

    Ask Claude to plan before it acts, and read the plan. It requests permission before running commands or changing files — approve only what you understand.

  4. 5:18
    Seeing files change

    You can watch which files are created and edited. For video work this means new exports appear in your folder as it works.

  5. 6:01
    Working with your real files

    Point Claude Code at a folder. Use a copy of your footage: originals should always be backed up somewhere it cannot touch.

  6. 7:34
    Rewind and recover

    You can step back when a change goes wrong. This protects text and project files; it is not a substitute for a backup of your media.

  7. 8:59
    When not to use it

    For a quick question or a script draft, a normal chat is simpler. Use Claude Code when the job involves files, tools or many repeated steps.

Session 3.2

FFmpeg basics

The free tool Claude uses behind the scenes to process video.

Video referenceyou need to learn FFmpeg RIGHT NOW!!DevOps Toolbox · 12:40 · YouTube ↗

Session notes
  • FFmpeg is a command-line program that converts, trims, joins and compresses video and audio.
  • You do not need to memorise commands — but understand input, output, codec and container.
  • Re-encoding costs quality and time; copying streams without re-encoding is fast and lossless.
Detailed notes · 6 parts
  1. 0:34
    Why FFmpeg

    FFmpeg is free software that powers a large share of the world's video processing. It has no interface: you tell it what to do in a single line of text.

  2. 2:50
    The basic command

    Every command has the same shape: the program, an input file, options and an output file. The output's extension decides the container, such as MP4 or MOV.

  3. 6:22
    Extracting audio

    You can pull the audio out of a video into its own file — useful for transcription, podcasts or sending sound for a mix.

  4. 6:56
    Compression

    Quality and file size are controlled by the codec and a quality setting. Lower quality numbers mean better quality and larger files; test on a short clip first.

  5. 10:27
    Automating

    Commands can be repeated across a whole folder — converting, resizing or renaming hundreds of clips while you do something else. This is where Claude writing the commands saves the most time.

  6. Part 6
    What to understand, not memorise

    Know the vocabulary: container, codec, bitrate, resolution, frame rate. With those words you can tell Claude exactly what you need and check that the command it proposes makes sense.

Screenshots are frames from the video, served by YouTube. Tap a time to open the video at that part.

Practice

Ask Claude Code to convert a clip to MP4, trim the first ten seconds and explain each part of the command.

  6. 10:25

Session 4.1

Automating the rough cut

A full walkthrough of an automated editing pipeline.

Video referenceI Fully Automated My Video Editing Using Claude Code (Full Walkthrough)Christian Peverelli · 16:59 · YouTube ↗

Session notes
  • A pipeline usually goes: transcribe, find the good takes, remove silences and mistakes, assemble.
  • The transcript is the map: Claude edits by reading words and timestamps.
  • Automation gives you a rough cut. Rhythm, emotion and story are still your job.
Detailed notes · 6 parts
  1. 0:31
    The roles in an editing team

    An automated pipeline copies a real team: someone to transcribe, someone to choose takes, an editor, a designer, a sound person and a reviewer. Each role becomes one step.

  2. 5:36
    The role of a Skill

    A Skill holds the instructions for one of those roles, so the same standards are applied every time without retyping them.

  3. 6:08
    Setting up the system

    Install the tools once, set up the folder structure and test each step on a short clip before running the whole pipeline.

  4. 9:41
    Training your AI editor

    Give examples of your finished edits and written rules: how long a pause may be, how fast the cuts are, what your captions look like.

  5. 11:36
    Editing in action

    Run the pipeline on real footage and watch each stage. Note every correction you make by hand — those notes become improvements to the instructions.

  6. 15:12
    Costs and limits

    Automation costs time to set up and money to run. It pays back on repeated formats such as a weekly series, not on one-off creative films.

Session 4.3

Repurposing long videos into shorts

Finding the moments worth clipping in a long recording.

Video referenceHow to Turn 1 Video Into 10+ YouTube Shorts Using AIThink Media · 11:45 · YouTube ↗

Session notes
  • Ask Claude to read the transcript and propose moments with a hook, a point and a clean ending.
  • A good clip makes sense without the rest of the video.
  • Watch every proposed clip yourself before publishing; context can be lost.
Detailed notes · 6 parts
  1. 0:00
    Why repurpose

    One long video contains several short ones. Shorts bring new viewers back to the full video and to the brand.

  2. 0:40
    Shorts from an existing long video

    Find self-contained moments: a strong statement, a tip, a short story. Give Claude the transcript and ask for candidates with start and end times and a suggested hook.

  3. 5:25
    An original short

    Some ideas are better filmed directly as a short. Script it tightly — one idea, one point, one ending.

  4. 9:09
    Shorts from other material

    Podcasts, live streams and webinars can be clipped the same way. Check you have the right to use everything in the clip.

  5. Part 5
    Reframing for vertical

    A wide shot must be reframed to 9:16 so the speaker stays centred. Check each cut — automatic reframing can lose the subject.

  6. Part 6
    Before publishing

    Watch every clip without the original context. If it does not make sense alone, extend it, add a caption line or drop it.

Session 5.3

Skills: teach Claude your editing style

Packaging your process so Claude repeats it every time.

Video referenceClaude Skills Explained - Step-by-Step Tutorial for BeginnersKevin Stratvert · 11:00 · YouTube ↗

Session notes
  • A Skill is a saved set of instructions and files Claude loads when a task needs it.
  • Write your editing rules down: pacing, caption style, music level, export settings.
  • Improve the Skill after each project instead of repeating corrections in chat.
Detailed notes · 6 parts
  1. 0:37
    What a Skill is

    A Skill is a folder of instructions, and optionally files and scripts, that Claude loads only when a task calls for it.

  2. 1:41
    Built-in Skills

    Claude includes ready-made Skills for common document types. They show how a Skill is structured before you write your own.

  3. 4:00
    Creating a Skill

    Describe the task, the steps and the standards in clear language. For editing, include pacing rules, caption style, music level, colour look and export settings.

  4. Part 4
    A good description

  6. 11:09
